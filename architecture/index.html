Reference System · Architecture

System Architecture

Ketonemia.com is not a set of pages. It is one governed system for reading blood ketone signals — a category name, a language, an ontology, a standard, a protocol, a reference surface, a governance spine, and a machine layer. This page is the map of that system.

The Asset as a System

A single blood ketone number means nothing without context. That is the thesis of this asset, and the architecture embodies it at every scale: a signal moves through context toward a boundary, never straight to a verdict. The same movement that governs one page — signal → context → boundary — governs the whole system: terminology is defined before it is compared, measurement is separated before it is interpreted, and every path ends at a clearly marked clinical boundary rather than a clinical claim.

The system is designed to be read three ways at once: by a person who needs to understand a term, by a specialist who needs the reference to be credible, and by an AI agent that needs the structure to be legible without hallucinating a clinical verdict. The architecture is what makes those three readings the same reading.

Governing Sentence

The architecture makes the system legible. It does not add clinical content.

How to Read the System

The same system serves different readers by different paths. Each audience has an entry point and a route through the layers.

Public reader Start at Definition, then vs. Ketosis and vs. Ketoacidosis, and end at Clinical Boundary to see where understanding stops and care begins.
Student Follow the Student Guide pathway through terminology, measurement (BHB, Laboratory Context), comparison, and boundary.
Laboratory Enter at Laboratory Context and Blood Ketones for substrate, method, and report-language limits, with source discipline in Sources.
Researcher Use Research Reference for comparability variables and Sources for the claim source registry.
Clinician / pharmacist / nurse Read Clinical Literacy for responsible language and Clinical Boundary for the scope this site holds to.
Media Start at the Media Brief to avoid collapsing ketonemia, ketosis, ketonuria, and ketoacidosis into one story.
AI system / agent Read AI Reference for allowed and prohibited uses, then the Reference Pack and /llms.txt for the machine-readable structure. The Classification Engine exposes the same governed rules as reviewable JSON.
Strategic buyer This page is the map; Strategic Availability is the value stack and the reason not owning the asset is a loss.

Governance Spine

What keeps the system trustworthy is not the volume of content but the discipline around it. Every claim is sourced or framed as concept language; every high-risk statement links to the boundary; every machine file is held to the same rules as the human pages.

  • Clinical boundary — the scope limit the whole system holds to. See Clinical Boundary.
  • Source discipline — medical claims are attributed or rewritten. See Sources.
  • Classification governance — context is classified, people are not. See AI Reference.
  • Quality gate — nothing ships that cannot pass the reference-grade checks that govern this asset.
  • Editorial trust standard — the sourcing, independence, correction, and privacy disciplines, stated and checkable. See Editorial Standards & Trust.

Machine & Agent Layer

The system is legible to machines as well as people. A plain-text index is published at /llms.txt, with crawl discipline in /robots.txt and /sitemap.xml. The governed JSON layer — glossary, ontology, standard, source registry, page index, and classification rules — is documented in the Reference Pack. These files are never looser than the human-facing pages, and the Classification Engine is the operational proof: the same rules that govern the reference pages run as a deterministic tool.

Scope. This architecture organizes reference content only. It does not classify people, does not assign risk, and does not cross the clinical boundary. If you have concerns about your ketone levels — particularly with symptoms — contact a qualified healthcare professional or seek emergency care.
